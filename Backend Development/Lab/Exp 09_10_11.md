## 5. Theory

### 5.1 Introduction to AJAX

AJAX stands for **Asynchronous JavaScript and XML**. It is a technique that allows a webpage to communicate with a server and update selected parts of the interface without reloading the entire page.

Despite XML appearing in its name, modern AJAX applications frequently exchange JSON data. AJAX is a technique, not a separate programming language or a specific data format.

Consider a student portal. When a student clicks "View Students", the webpage can request student records from a server and display them in a table without reloading the page.

The typical process is:

1. The user performs an action.
2. JavaScript sends an HTTP request.
3. The server processes the request and returns data.
4. JavaScript processes the response.
5. The webpage updates the relevant HTML elements.

### 5.2 Traditional Web Requests vs. AJAX

| Traditional approach                       | AJAX approach                                         |
| ------------------------------------------ | ----------------------------------------------------- |
| Often reloads the complete page            | Can update only the required section                  |
| User may experience a visible page refresh | Existing interface can remain visible                 |
| Response may contain a complete HTML page  | Response can contain JSON, XML or HTML                |
| Suitable for conventional page navigation  | Suitable for search, filtering and dynamic dashboards |

AJAX does not eliminate HTTP requests. It changes how requests are initiated and how their responses are used by the webpage.

### 5.3 What Is XML?

XML (Extensible Markup Language) represents data using nested, user-defined tags. It is useful when data requires a hierarchical structure or must follow an XML-based interchange format.

Example:

```
<?xml version="1.0" encoding="UTF-8"?>
<students>
    <student id="101">
        <name>Aarav</name>
        <course>B.Tech CSE</course>
    </student>
    <student id="102">
        <name>Meera</name>
        <course>B.Tech IT</course>
    </student>
</students>
```

The browser can parse this document and extract individual student records using the DOM API.

### 5.4 What Is JSON?

JSON (JavaScript Object Notation) is a lightweight text format for exchanging structured data. It represents objects using key-value pairs and arrays using ordered collections of values.

Example:

```
{
  "students": [
    {
      "id": 101,
      "name": "Aarav",
      "course": "B.Tech CSE"
    },
    {
      "id": 102,
      "name": "Meera",
      "course": "B.Tech IT"
    }
  ]
}
```

JSON is widely used by REST APIs because it is compact, easy to generate, and supported by most programming languages. JavaScript provides `response.json()` for parsing JSON responses.

### 5.5 XML vs. JSON

| Feature               | XML                                  | JSON                                |
| --------------------- | ------------------------------------ | ----------------------------------- |
| Structure             | Nested elements and attributes       | Objects and arrays                  |
| Data representation   | Tags surrounding content             | Keys and values                     |
| Parsing in JavaScript | `DOMParser` or XML DOM               | `response.json()` or `JSON.parse()` |
| Common use            | XML-based integrations and documents | REST APIs and web applications      |
| Typical readability   | More verbose                         | More compact                        |

Neither format is universally superior. The appropriate format depends on the API contract, the application and the systems being integrated.

### 5.6 What Is jQuery?

jQuery is a JavaScript library that simplifies DOM manipulation, event handling, animation and AJAX operations.

Its common syntax is:

```
// Select elements using CSS-style selectors.
$("p").hide();

// Register a click handler.
$("#loadButton").on("click", function () {
    alert("Button clicked");
});
```

The `$` function selects elements or creates jQuery objects. Methods such as `.on()`, `.html()` and `.text()` provide convenient ways to interact with the webpage.

jQuery remains useful in legacy projects and educational exercises. Modern applications can perform many of the same tasks using native JavaScript APIs.

### 5.7 AJAX Using Modern JavaScript and jQuery

Modern JavaScript provides the Fetch API for asynchronous HTTP requests:

```
// Retrieve JSON data and handle the response.
fetch("students.json")
    .then(response => {
        if (!response.ok) {
            throw new Error("Unable to load students");
        }
        return response.json();
    })
    .then(data => console.log(data.students))
    .catch(error => console.error(error));
```

jQuery provides a corresponding AJAX utility:

```
// Retrieve and process JSON data using jQuery.
$.ajax({
    url: "students.json",
    method: "GET",
    dataType: "json",
    success: function (data) {
        console.log(data.students);
    },
    error: function () {
        console.error("Unable to load students");
    }
});
```

Both approaches allow the webpage to retrieve data asynchronously. The jQuery example depends on the jQuery library being loaded.

### 5.8 Connection to Backend Development

A frontend application frequently communicates with backend services through HTTP requests. In a production system, the request might target an endpoint such as `/api/students`, and the backend would retrieve records from a database before returning JSON.

In this experiment, static XML and JSON files simulate the data source so that students can focus on the client-side request and response process. A later extension can replace those files with a real Node.js, Express, Flask or Django API.

### 5.9 Common Applications

AJAX and JSON are used in:

- Search suggestions and live filtering
- Student and employee dashboards
- Shopping cart updates
- Notifications and status updates
- Dynamic forms
- Analytics dashboards
- Data-driven administrative portals

### 5.10 Responsible Use of AI

AI assistants can explain asynchronous code, generate test data and help diagnose JavaScript errors. However, students should verify that the generated program handles HTTP errors, uses safe DOM updates and processes the correct response format.

Create `app.js`:

```
const tableBody = document.querySelector("#studentTable");
const statusMessage = document.querySelector("#status");

// Build table rows from trusted data using textContent.
function displayStudents(students) {
    tableBody.replaceChildren();

    students.forEach(student => {
        const row = document.createElement("tr");

        [student.id, student.name, student.course].forEach(value => {
            const cell = document.createElement("td");

            // textContent treats values as text rather than HTML.
            cell.textContent = value;
            row.appendChild(cell);
        });

        tableBody.appendChild(row);
    });
}

// Fetch JSON data without reloading the webpage.
document.querySelector("#loadJson").addEventListener("click", async () => {
    statusMessage.textContent = "Loading JSON data...";

    try {
        const response = await fetch("students.json");

        // fetch() does not reject automatically for HTTP 404 or 500.
        if (!response.ok) {
            throw new Error(`HTTP error: ${response.status}`);
        }

        const data = await response.json();
        displayStudents(data.students);
        statusMessage.textContent = "JSON data loaded successfully.";
    } catch (error) {
        statusMessage.textContent = `Error: ${error.message}`;
    }
});
```

**Procedure:**

1. Save all files.
2. Open the webpage through Live Server.
3. Click **Load JSON Students**.
4. Observe the table being populated without a full-page reload.
5. Open browser DevTools and select the Network tab.
6. Click the button again and inspect the request for `students.json`.

**Code explanation:**

- `fetch()` initiates an HTTP request.
- `response.ok` checks whether the HTTP response indicates success.
- `response.json()` parses the response body into JavaScript data.
- `displayStudents()` creates and inserts table rows.
- `textContent` displays values safely as text.
- `async` and `await` make asynchronous code easier to read.

**Expected output:** The three student records appear in the table after the user clicks the JSON button.

### Part D — Retrieve and Process XML Data

**Objective:** Fetch an XML document and convert its records into table rows.

Add the following code to `app.js`:

```
// Fetch XML data and parse its document structure.
document.querySelector("#loadXml").addEventListener("click", async () => {
    statusMessage.textContent = "Loading XML data...";

    try {
        const response = await fetch("students.xml");

        if (!response.ok) {
            throw new Error(`HTTP error: ${response.status}`);
        }

        const xmlText = await response.text();

        // Convert the received text into an XML document.
        const xmlDocument = new DOMParser().parseFromString(
            xmlText,
            "application/xml"
        );

        // Detect malformed XML before reading student records.
        if (xmlDocument.querySelector("parsererror")) {
            throw new Error("The XML document is invalid.");
        }

        const students = Array.from(
            xmlDocument.querySelectorAll("student")
        ).map(student => ({
            id: student.getAttribute("id"),
            name: student.querySelector("name").textContent,
            course: student.querySelector("course").textContent
        }));

        displayStudents(students);
        statusMessage.textContent = "XML data loaded successfully.";
    } catch (error) {
        statusMessage.textContent = `Error: ${error.message}`;
    }
});
```

**Procedure:**

1. Save `app.js`.
2. Reload the webpage.
3. Click **Load XML Students**.
4. Verify that the same records appear in the table.
5. Inspect the Network tab and compare the XML and JSON requests.
6. Temporarily introduce an error into `students.xml` and observe how the program reports malformed XML.

**Code explanation:**

- `response.text()` reads the XML response as text.
- `DOMParser` converts the text into an XML document.
- `querySelectorAll("student")` locates each student element.
- `getAttribute("id")` reads the student's identifier.
- `textContent` extracts the contents of XML elements.

**Expected output:** The same student records are displayed when XML is loaded. The interface remains unchanged; only the source and parsing method differ.

### Part E — Use jQuery for DOM Manipulation and AJAX

**Objective:** Implement an equivalent JSON retrieval operation using jQuery.

Add the following line to `index.html` immediately before `app.js` is loaded:

```
<!-- Load jQuery before application code that uses $. -->
<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>
```

Replace the existing JSON button handler in `app.js` with the following jQuery version. Keep the XML handler and the `displayStudents()` function.

```
// Use jQuery to register the JSON loading event.
$("#loadJson").on("click", function () {
    $("#status").text("Loading JSON data...");

    // Perform an asynchronous HTTP GET request.
    $.ajax({
        url: "students.json",
        method: "GET",
        dataType: "json",

        // Execute this callback when valid JSON is received.
        success: function (data) {
            displayStudents(data.students);
            $("#status").text("JSON data loaded using jQuery.");
        },

        // Handle network, HTTP and parsing failures.
        error: function (xhr, status, error) {
            $("#status").text(`Request failed: ${error || status}`);
        }
    });
});
```

**Procedure:**

1. Save and reload the webpage.
2. Click **Load JSON Students**.
3. Verify that the records appear.
4. Observe how jQuery's `$()` selector accesses the page elements.
5. Compare the `$.ajax()` approach with the Fetch API implementation.
6. Disconnect from the internet or block the CDN request to observe what happens when jQuery fails to load. Restore connectivity before continuing.

**Code explanation:**

- `$("#loadJson")` selects the button by its ID.
- `.on("click", ...)` registers an event handler.
- `$.ajax()` sends an asynchronous HTTP request.
- `dataType: "json"` tells jQuery to interpret the response as JSON.
- `success` handles a successful request.
- `error` handles request failures.

**Expected output:** The jQuery implementation displays the same JSON records as the Fetch API implementation.

**Important:** Do not keep both JSON click handlers active simultaneously. Otherwise, one click may trigger two requests.

## 8. Connection to Backend Development

The experiment uses static files, but the same client-side technique can retrieve data from a backend API.

For example, a production application might request:

```
GET /api/students
```

The backend would process the request, retrieve student information from a database, and return a JSON response. The frontend would parse that response and update the table using the same general pattern demonstrated here.

This is the foundation of asynchronous communication in full-stack applications.

## 9. Conclusion

The experiment demonstrates how AJAX enables webpages to retrieve data asynchronously without reloading the complete page. Students process JSON using the Fetch API, retrieve and parse XML using `DOMParser`, and implement jQuery-based AJAX and DOM manipulation. They also learn to inspect HTTP requests using browser DevTools and handle common errors. These concepts provide a foundation for consuming RESTful APIs and integrating frontend applications with backend servers and databases.
