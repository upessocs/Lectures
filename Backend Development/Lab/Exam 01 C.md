# Backend Development Lab Examination

## Objective

Design and develop a **Blog Content Management System (CMS)** using either Node.js or Python. The application must use server-side templates and store blog posts in the existing MongoDB database.

The application should allow users to create blog posts, view a list of posts, and open an individual post by clicking its title.

**Duration:** 60 minutes
**Maximum Marks:** 30

## Technology Options

Choose any **one** stack:

| Option | Backend                      | Template Engine | MongoDB Library                    |
| ------ | ---------------------------- | --------------- | ---------------------------------- |
| A      | Node.js with Express.js      | EJS             | MongoDB Node.js Driver or Mongoose |
| B      | Python with Flask or FastAPI | Jinja2          | PyMongo or Motor                   |

## Problem Statement

Develop a web application named **Simple CMS** that allows users to create and read blog posts.

Each post should contain:

* Title
* Content
* Author
* Creation date and time

The creation date and time must be generated automatically by the **backend** when the post is created. The user should not enter this value manually.

## Compulsory Requirements

### 1. Display All Posts

Create a home page that retrieves all posts from MongoDB and displays them as a list.

Each post should initially show:

* Title
* Author
* Creation date

For example:

```text
Backend Development
By Rahul
26 September 2026

Introduction to MongoDB
By Priya
26 September 2026

Building Web Applications
By Amit
25 September 2026
```

The **title of each post must be clickable**.

### 2. Create a Post

Create an HTML form containing:

* Title
* Content
* Author
* Submit button

When the form is submitted:

1. Validate that the title is not empty.
2. Validate that the content is not empty.
3. Validate that the author is not empty.
4. Insert the post into MongoDB.
5. Generate the creation date automatically on the server.
6. Redirect the user to the post list page.

The date must not be entered through the form.

### 3. View Individual Post

When the user clicks the title of a post, display the **complete post**.

For example:

```text
Introduction to MongoDB

By Priya
26 September 2026

MongoDB is a document-oriented database that stores
data in flexible JSON-like documents.

It is commonly used with modern web applications
because it provides a flexible data model.
```

The individual post page must retrieve the selected post from MongoDB using its unique ID.

The complete content should **not** be sent as part of the post-list page.

### 4. Server-Side Templates

The pages must be rendered using:

* EJS for Node.js, or
* Jinja2 for Python.

At least the following pages should be implemented:

```text
Post List
    |
    +----> Create Post
    |
    +----> Click Post Title
                |
                +----> Complete Post
```

### 5. MongoDB Persistence

Posts must be stored permanently in MongoDB.

Refreshing the browser or restarting the backend application must not remove previously created posts.

# Node.js Hints

## Install Packages

```bash
npm init -y
npm install express ejs mongodb
```

## Connect to MongoDB

```javascript
const { MongoClient, ObjectId } = require("mongodb");

const mongoURL = "mongodb://127.0.0.1:27017";
const client = new MongoClient(mongoURL);

let postsCollection;

async function connectDB() {
    await client.connect();

    const database = client.db("cms_lab");
    postsCollection = database.collection("posts");

    console.log("Connected to MongoDB");
}

connectDB();
```

Reuse the same `MongoClient` instead of creating a new connection for every request.

## Configure Express and EJS

```javascript
const express = require("express");
const app = express();

app.set("view engine", "ejs");

// Parse data submitted through HTML forms.
app.use(express.urlencoded({ extended: true }));

// Serve CSS, JavaScript and other static files.
app.use(express.static("public"));
```

## Retrieve All Posts

```javascript
const posts = await postsCollection
    .find()
    .sort({ createdAt: -1 })
    .toArray();
```

## Insert a Post

```javascript
await postsCollection.insertOne({
    title: req.body.title,
    content: req.body.content,
    author: req.body.author,

    // Generate the creation time on the server.
    createdAt: new Date()
});
```

## Retrieve One Post

```javascript
const post = await postsCollection.findOne({
    _id: new ObjectId(req.params.id)
});
```

The `ObjectId` is obtained from the URL:

```text
/posts/68d5a123456789abcdef1234
```

# Python Flask Hints

## Install Packages

```bash
pip install flask pymongo
```

## Connect to MongoDB

```python
from flask import Flask, render_template, request, redirect
from pymongo import MongoClient
from bson.objectid import ObjectId
from datetime import datetime

app = Flask(__name__)

client = MongoClient("mongodb://127.0.0.1:27017")
database = client["cms_lab"]
posts_collection = database["posts"]
```

## Retrieve All Posts

```python
posts = list(
    posts_collection.find().sort("createdAt", -1)
)
```

## Insert a Post

```python
posts_collection.insert_one({
    "title": request.form["title"],
    "content": request.form["content"],
    "author": request.form["author"],

    # Generate the creation time on the server.
    "createdAt": datetime.now()
})
```

## Retrieve One Post

```python
post = posts_collection.find_one({
    "_id": ObjectId(post_id)
})
```

## Important Requirements

1. The application must use **MongoDB** for storing posts.
2. The application must use **server-side rendering** with EJS or Jinja2.
3. The `createdAt` value must be generated by the backend.
4. The post list must retrieve data from MongoDB.
5. Each post title must be a clickable link.
6. Clicking a title must open a separate page containing the **complete post**.
7. The individual post must be retrieved using its MongoDB `_id`.
8. The complete content should not simply be embedded in the post-list page and shown/hidden using JavaScript.
9. Empty title, content, or author values must not be accepted.
10. Authentication, REST APIs, user accounts, and frontend frameworks are **not required**.
