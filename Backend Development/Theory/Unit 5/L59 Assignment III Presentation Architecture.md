## Part A – Presentation Blueprint

Students should organize the presentation as: **problem → concept → architecture/flow → implementation choices → real-world use case → limitations and trade-offs → conclusion → questions**.

### Topic-Specific Hints

- WebSockets: handshake, persistent channel, message lifecycle.
- Socket.io: events, rooms, broadcasting, raw WebSocket comparison.
- Microservices: decomposition, benefits, operational cost.
- Discovery: registration, health checks, dynamic routing.
- REST: gateway, sequence diagram, timeouts and retries.
- Messaging: producer, broker, consumer, delivery and consistency.
- Serverless: trigger, function, limits, cost, cold start.
- Cloud functions: handler, configuration, permissions, logs.
- Event-driven serverless: event bus, queue, retry, dead-letter path.
- Profiling: baseline, measurement, bottleneck, improvement evidence.

## PBL Activity

Prepare 8–12 slides for a 15-minute delivery. Include one main diagram, one comparison or trade-off slide, one real-world example, two to four questions with answers, contribution details, and annotated references.

## Assessment Activity

Peer reviewers check conceptual clarity, diagram accuracy, evidence, originality, timing, equal participation, and reference quality.

## Summary

- A presentation is an argument, not a collection of definitions.
- Every diagram should explain a flow, boundary, or decision.
- References should contribute insight and be discussed, not merely listed.
