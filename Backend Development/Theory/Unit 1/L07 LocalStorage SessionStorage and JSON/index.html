1. What is Web Storage?

Web Storage is a browser API that lets JavaScript store key-value pairs on the client side. There are two types:

localStorage

  • Data persists forever until you delete it
  • Shared across all tabs (same origin)
  • ~5-10 MB storage limit

sessionStorage

  • Data dies when the tab closes
  • Isolated per tab
  • ~5-10 MB storage limit
Key Rule: Both only store strings. You must use JSON to store objects.

4. The JSON Problem — Why Can't We Store Objects?

Storage only accepts strings. Watch what happens when you try to store an object directly:

// Run this in console (F12)
const user = { name: "Alice", age: 25 };
localStorage.setItem("user", user);

console.log(localStorage.getItem("user"));
// Output: "[object Object]"  — USELESS!
//
// The object was converted to its default string representation.
// We lost all our data!

The fix: Convert to JSON string first

localStorage.setItem("user", JSON.stringify(user));

console.log(localStorage.getItem("user"));
// Output: '{"name":"Alice","age":25}'  — Full data preserved!

5. JSON.stringify() — Object to String

What It Does

Takes a JavaScript value (object, array, number, etc.) and converts it to a JSON string.

// Simple object
JSON.stringify({ name: "Bob", age: 30 })
// → '{"name":"Bob","age":30}'

// With array
JSON.stringify({ name: "Bob", skills: ["JS", "Python"] })
// → '{"name":"Bob","skills":["JS","Python"]}'

// Pretty-printed (with indentation)
JSON.stringify({ name: "Bob" }, null, 2)
// → '{
//      "name": "Bob"
//    }'

// Just a value
JSON.stringify("hello")  // → '"hello"'
JSON.stringify(42)       // → '42'
JSON.stringify(true)     // → 'true'

6. JSON.parse() — String to Object

What It Does

Takes a JSON string and converts it back to a JavaScript value.

const jsonString = '{"name":"Bob","age":30,"skills":["JS","Python"]}';

const obj = JSON.parse(jsonString);
console.log(obj.name);    // "Bob"
console.log(obj.age);     // 30
console.log(obj.skills);  // ["JS", "Python"]

The Full Round-Trip

const user = { name: "Alice", hobbies: ["reading", "coding"] };

// SAVE to storage
localStorage.setItem("user", JSON.stringify(user));

// READ from storage
const saved = JSON.parse(localStorage.getItem("user"));

console.log(saved.hobbies[0]);  // "reading"
console.log(typeof saved);      // "object" — it's back!
Warning: If the stored string is not valid JSON, JSON.parse() throws an error! Always wrap it in try...catch. 
try {
    const data = JSON.parse("not valid json");
} catch (e) {
    console.error("Parse failed:", e.message);
    // "Parse failed: Unexpected token n in JSON at position 0"
}

Write these two helper functions in the console and use them for all future exercises:

function save(key, data) {
    localStorage.setItem(key, JSON.stringify(data));
}

function load(key) {
    const raw = localStorage.getItem(key);
    return raw ? JSON.parse(raw) : null;
}

// Now you can do:

11. Common Mistakes

Mistake 1: Forgetting JSON.stringify

// WRONG
localStorage.setItem("user", {name: "Bob"});
// → "[object Object]" — lost data!

// RIGHT
localStorage.setItem("user", JSON.stringify({name: "Bob"}));

Mistake 2: Forgetting JSON.parse

// WRONG
const user = localStorage.getItem("user");
console.log(user.name);  // undefined — it's a string!

// RIGHT
const user = JSON.parse(localStorage.getItem("user"));
console.log(user.name);  // "Bob"

Mistake 3: Not handling null / missing keys

// This crashes if "user" doesn't exist!
const user = JSON.parse(localStorage.getItem("user"));
// → null → JSON.parse(null) = null → user.name → TypeError!

// SAFE approach
const raw = localStorage.getItem("user");
const user = raw ? JSON.parse(raw) : null;

Mistake 4: Assuming data types survive round-trip

localStorage.setItem("num", 42);
typeof localStorage.getItem("num");  // "string" not "number"!

12. Final Task — Build a Notes App

Your Mission

Build a fully functional Notes / Todo app using only frontend HTML/CSS/JS with localStorage for persistence.

Requirements

Must Have

  • Add a new note with text
  • Display all saved notes on page load
  • Delete individual notes
  • Edit existing notes
  • Data persists after page refresh (localStorage)
  • Each note has: id, text, createdAt, updatedAt

Nice to Have (stretch goals)

  • Mark notes as complete / incomplete
  • Search/filter notes
  • Note categories or tags
  • Import / Export notes as JSON file
  • Dark/Light mode toggle (saved preference)
  • Drag to reorder notes

Hints & Starter Pattern

Step 1 — Data Structure

// Each note
const note = {
    id: Date.now(),          // unique ID
    text: "My first note",
    completed: false,
    createdAt: new Date().toISOString(),
    updatedAt: null
};

// Array of notes (the "database")
// Saved as: localStorage.setItem("notes", JSON.stringify(notes))

Step 2 — Helper Functions

function getNotes() {
    const raw = localStorage.getItem("notes");
    return raw ? JSON.parse(raw) : [];
}

function saveNotes(notes) {
    localStorage.setItem("notes", JSON.stringify(notes));
}

Step 3 — CRUD Operations

// CREATE
function addNote(text) {
    const notes = getNotes();
    notes.push({
        id: Date.now(),
        text: text,
        completed: false,
        createdAt: new Date().toISOString(),
        updatedAt: null
    });
    saveNotes(notes);
    renderNotes();
}

// READ (already done via getNotes)

// UPDATE
function updateNote(id, newText) {
    const notes = getNotes();
    const note = notes.find(n => n.id === id);
    if (note) {
        note.text = newText;
        note.updatedAt = new Date().toISOString();
        saveNotes(notes);
        renderNotes();
    }
}

// DELETE
function deleteNote(id) {
    const notes = getNotes().filter(n => n.id !== id);
    saveNotes(notes);
    renderNotes();
}

Step 4 — Render to DOM

function renderNotes() {
    const container = document.getElementById("notesList");
    const notes = getNotes();
    container.innerHTML = notes.map(note => `
        <div class="note-card">
            <p>${note.text}</p>
            <button onclick="deleteNote(${note.id})">Delete</button>
            <button onclick="editNote(${note.id})">Edit</button>
        </div>
    `).join("");
}

Step 5 — HTML Skeleton

<input type="text" id="noteInput" placeholder="Type a note...">
<button onclick="addNote(document.getElementById('noteInput').value)">
    Add Note
</button>
<div id="notesList"></div>

<script>
    // Put all JS here
    window.onload = renderNotes;
</script>

What Changes in the Code

Before (Frontend Only)

    return JSON.parse(localStorage.getItem("notes")) || [];

After (With Backend API)

// Backend API calls
async function getNotes() {
    const res = await fetch("/api/notes", {
        headers: { "Authorization": "Bearer " + token }
    });
    return await res.json();
}

async function addNote(text) {
    const res = await fetch("/api/notes", {
        method: "POST",
        headers: {
            "Content-Type": "application/json",
            "Authorization": "Bearer " + token
        },
        body: JSON.stringify({ text })
    });
    return await res.json();
}

async function deleteNote(id) {
    await fetch(`/api/notes/${id}`, {
        method: "DELETE",
        headers: { "Authorization": "Bearer " + token }
    });
}

Storage Strategy Pattern

The best approach: use localStorage as cache, backend as source of truth.

async function getNotes() {
    // 1. Try cache first (fast, offline)
    const cached = localStorage.getItem("notes");
    if (cached) return JSON.parse(cached);

    // 2. Fetch from server
    const res = await fetch("/api/notes");
    const notes = await res.json();

    // 3. Cache for next time
    localStorage.setItem("notes", JSON.stringify(notes));
    return notes;
}

async function addNote(text) {
    // 1. Save to server first
    const res = await fetch("/api/notes", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ text })
    });
    const note = await res.json();

    // 2. Update local cache
    const notes = JSON.parse(localStorage.getItem("notes")) || [];
    notes.push(note);
    localStorage.setItem("notes", JSON.stringify(notes));

    return note;
}

Key Takeaway

localStorage is not a replacement for a database. It's a tool for:

  • Caching server responses
  • Storing user preferences
  • Offline functionality
  • Temporary data during sessions

For real apps, always use a backend with a proper database. Use localStorage as a complement, not a replacement.
