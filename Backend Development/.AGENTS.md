# Standard Experiment Manual Structure

All new experiment manuals MUST follow this structure and be **fully self-sufficient** (student should not need external resources to complete the lab).

## Required Sections

### 1. Objective
One-line goal of the experiment.

### 2. Theory
Concise explanation of core concepts. Use bullet points and tables. Include:
- What the concept is and why it exists.
- Key terminology with brief definitions.
- Comparison tables where relevant.

### 3. Hands-on Tasks (Step-by-Step)
Each task must follow this pattern:
1. **What** - Brief description of what we are building.
2. **Complete Code** - Full runnable code (not fragments). Each step builds on the previous.
3. **What Changed** - 1-2 lines explaining what was added/modified.

Tasks are incremental: Task 1 → Task 2 builds on Task 1's output.

### 4. Concepts Reference
Detailed explanation of key APIs/classes/syntax used, grouped logically (e.g., "Spacing Classes", "Color Classes", "Breakpoints").

### 5. Exercises
2-3 practice problems of increasing difficulty.

### 6. Viva Questions
3-5 questions with short answers.

### 7. References
Links to official documentation.

## Code Style Rules
- Every code block must be a **complete, runnable file** (or clearly marked snippet if partial).
- Use `<!-- filename: xxx.html -->` comment before code blocks.
- No placeholder comments like `<!-- add more here -->` in task code.
